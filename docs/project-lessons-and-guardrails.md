# 项目经验与开发红线

本文记录 BSF 项目已经踩过的坑，以及后续开发必须遵守的规则。

## 一、必须遵守

1. 不要擅自扩大修改范围。
   - 只修改用户明确指定的页面和功能。
   - 不自行添加说明文字、按钮或复杂交互。
   - 不随意改变原版布局、权限和数据结构。

2. 所有限制必须在后端再次校验。
   - 前端的 Client/Machine 权限限制只负责界面体验。
   - 后端必须校验 JWT/会话、角色、Client 和 Machine 归属。
   - 不能允许通过直接调用 API 绕过界面限制。

3. 只允许一个 bms_mos.exe 实例运行。
   - 多个实例会重复订阅同一 MQTT Topic。
   - 同一数据会重复入库并在 Raw Data 中显示两次。
   - 启动前先检查端口和进程。

4. Gateway 数据读取规则。
   - `/api/messages?limit=N` 返回的是最早 N 条，不是最新 N 条。
   - 实时设备数据必须使用 `/api/latest`。
   - 历史列表必须排序后再截取最新记录。
   - Raw Data 显示使用服务器 `receivedAt`，避免设备时间戳错误造成误判。
   - 按 `设备 ID + 设备 timestamp` 去重。

5. 实时更新规则。
   - 当前 bms_mos 没有 WebSocket/SSE，只能轮询。
   - 页面每 5 秒读取一次最新数据。
   - 有新数据时自动更新，不要求用户刷新页面。
   - 数据未变化时不要重复重绘页面。

6. Client、Machine、User 关联规则。
   - 未关联设备显示为 `Unassigned`。
   - Machine 改绑新 Client 时，以最新关联为准。
   - 优先停用 Machine，不物理删除，避免破坏历史数据。
   - Machine Account 应显示关联 Client 和 User。

7. 角色数据范围。
   - Master Admin：全部 Client 和 Machine。
   - Client Admin：只能查看所属 Client 及其机器。
   - User：只能查看账号关联的唯一 Machine。
   - Client Admin/User 不显示 All Clients 和 All Machines。

8. PDF 导出规则。
   - 格式以客户 PPT 的 PDF 样板为准。
   - Generate Preview 只更新预览，不导出文件。
   - Export PDF 负责生成并保存 PDF。
   - 注意浏览器下载管理器和弹窗权限，避免下载显示“已停止”。

9. 后端未配置时的处理。
   - 不要伪装保存成功。
   - System Settings、密码修改、Machine 停用等必须明确依赖后端。
   - 客户界面不要出现 backend API、saved locally 等内部技术用语。

## 二、已经踩过的坑

### 1. 前端一直显示旧数据

原因：`/api/messages?limit=100` 返回最早 100 条，前端误认为是最新 100 条。

修复：使用 `/api/latest` 获取实时设备数据，并排序后取最新历史记录。

### 2. Raw Data 出现重复数据

原因：同时运行两个 `bms_mos.exe`，两个实例重复订阅和入库。

修复：停止重复实例；前端按设备 ID 和设备 timestamp 去重。

### 3. 实时轮询报错

原因：实时函数错误引用了未定义的 `messages` 变量。

修复：实时函数只使用 `latest`；完整加载函数单独处理消息列表。

### 4. 下载 PDF 被标记为已停止

原因：浏览器下载管理和临时 Blob/打印窗口处理不稳定。

修复：接入本地 jsPDF，优先直接写入文件，并提供下载回退。

### 5. Client Filter 为空时误操作全部设备

原因：筛选结果为空时错误回退到全部设备。

修复：筛选为空时停止操作并提示，不回退到全部数据。

### 6. 自行添加了不合适的文案

问题：客户界面出现了 backend API、saved locally 等内部词语。

规则：客户界面只使用普通、简洁、非技术化提示。

### 7. 修改文件时参数写错

问题：一次文件写入参数错误，导致 Raw Data 文件被覆盖。

修复：从 Git 最近提交恢复。后续修改必须：

1. 写前检查目标路径。
2. 写后立即执行语法检查。
3. 使用 Git 检查差异。
4. 不允许在未验证的情况下继续提交。
